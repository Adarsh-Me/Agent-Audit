# Fix the ba545a33 crash: forced-choice nulls + masked DB errors, then rerun femella

Root cause chain: (1) `parse.py` accepts `"product_id": null` as a VALID parse even in forced-choice conditions → no retry, violation enters batch, poison cached; (2) the batch commit failed with an unknown DB error (SQLite defaults: no WAL/busy_timeout, OneDrive-synced path) and the semantics guard living ONLY in the except block replaced the real error with a misleading AssertionError; (3) run marked failed, 40 trials lost.

## Backend changes

### 1. `app/engine/parse.py`
- Add `null_allowed: bool = True` param to `parse_response`.
- In `finish()`: when `choice is None and not null_allowed` → return `ParsedChoice(None, reason, False, "declined although choice was forced")` so the existing PARSE_RETRIES feedback loop re-asks the model; after retries it counts as an honest parse failure instead of poisoning the batch.
- Apply the same rule on the salvage-regex path.

### 2. `app/engine/runner.py` — `_execute_trial`
- Pass `null_allowed=spec.null_allowed` into `parse_response`.
- Cache-replay validation: in the cache branch, if `not spec.null_allowed and cached choice is None` → ignore the entry and take the live path (permanently neutralizes the already-poisoned cache row without a migration).

### 3. `app/engine/runner.py` — batch persistence honesty
- Validate each Trial at construction time (violating state impossible by construction); keep a pre-commit scan BEFORE `add_all` that raises a clearly-worded error — outside any except block.
- In the commit except path: `logger.exception(...)` and re-raise the ORIGINAL exception; abort_reason carries its real type/message instead of the mislabel.
- Retry transient commit failures: up to 3 attempts with 1s/2s/4s backoff on SQLAlchemy OperationalError.
- Flush partial batches every 20 trials or ~45s so the dashboard counter moves smoothly and the loss window shrinks from 40 to ≤20 trials.

### 4. `app/db/session.py` — SQLite hardening
- On connect (sync-engine event listener): `PRAGMA journal_mode=WAL`, `PRAGMA busy_timeout=15000`, `PRAGMA synchronous=NORMAL`.

### 5. `app/routers/audit.py` — eta_s realism
- Replace fixed 0.35 s/trial with rolling throughput from recent batches (or null while insufficient data) — current formula claimed 168s when ~75 min remained.
